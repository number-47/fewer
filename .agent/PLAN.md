## 运行时稳定性计划（R0–R6）

> 用户实机反馈优先于先前的构建/单测结论。T011 的 4pt 点击阈值与 16pt 方向阈值形成 5–15pt 的吞点击区间，原验收不成立，已由 T021 替代。

| 阶段 | Task | 标题 | 依赖 | 优先级 |
|------|------|------|------|--------|
| R0 | T020 | 真实运行基线与扩展问题扫描 | 无 | P0 |
| R1 | T021 | 右键事件完整性与鼠标手势状态机 | T013, T020 | P0 |
| R2 | T022 | 权限与扩展启用中心 | T013, T020 | P0 |
| R3 | T023 | Finder 菜单可见性与生命周期修复 | T013, T020, T021, T022 | P0 |
| R4 | T024 | 菜单栏日历滚动性能 | T013, T020 | P1 |
| R5 | T025 | 设置窗口响应与后台状态刷新 | T013, T020, T022 | P1 |
| R6 | T026 | 稳定性回归与第二轮问题收敛 | T021, T022, T023, T024, T025 | P0 |

已确认的计划依据：

- 当前手势在存在匹配按钮规则时从 `mouseDown` 起吞掉整段事件；4pt 点击容差与 16pt 识别段长之间会丢失普通右键。
- 超时/应用切换后会清空 session，但后续真实 `mouseUp` 可能继续透传，形成错配；超时回放还可能与真实序列叠加。
- 设置概览每秒在 MainActor 同步执行 `pluginkit` 并 `waitUntilExit`；多个设置 binding 在滑块连续变化时同步写盘并广播。
- 实际展示的输入诊断卡只有状态，没有权限按钮；带按钮的旧 `diagnostics` 视图没有被当前 tab 使用。
- 日历滚动每次更新 SwiftUI offset，并在每个周锚点变化时同步查询 EventKit、取消并重启提醒请求。

推荐顺序：T020 → T013 → T021 →（T022、T024）→（T023、T025）→ T026。稳定性 P0 完成前，不进入会扩大输入/Finder 变更面的架构任务。

## 明确延期

- 大文件按行数拆分：仅在当前任务自然形成职责边界时拆分，不单独做机械重构。
- `ENABLE_USER_SCRIPT_SANDBOXING` 与 Helper 原生嵌入：属于打包链路改造，需单独验证 XcodeGen/Xcode 的 LoginItems Copy Files 行为，不混入 CI 清理。
- Store 跨进程并发写协议和损坏设置恢复：另建任务，不与一次性路径迁移混合。
- 滚动截图文件后端/分块导出：当前 API 返回单个 `CGImage`，若要突破整图内存模型，需要另行改变导出契约。

## 关键决策

- GPU 默认启用并预置迷你百分比，但首次安装和升级均不自动显示菜单栏状态项。
- SMC、IOReport、SMART 与 Wi-Fi 定位失败一律降级为“不可用”，不伪造 0。
- CPU 不注册菜单栏快捷操作；工具箱及系统模块命令保持不变。
- App Group 迁移首个版本只复制、不删除旧数据；Finder `/` 例外必须在签名实机矩阵通过后移除。
- 特权命令不允许静默回退到无身份验证的 DistributedNotificationCenter。
- 右键物理序列必须只有一个终态：普通点击、执行一个手势动作、或已激活但未匹配而静默结束；禁止合成点击与真实残余事件叠加。
- 权限页必须准确区分主 App、Shortcut Helper、Finder Extension 三个授权主体，不把 Event Tap 运行状态冒充输入监控授权状态。
