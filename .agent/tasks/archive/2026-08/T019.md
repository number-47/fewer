# T019: PR7 — 滚动截图后台合成与显式内存预算

## 元信息

- 优先级：P1
- 状态：DONE

- 依赖：T013

## Goal

把最终 `StitchEngine.compose` 移出 MainActor，并在分配 `CGContext` 前用安全算术执行显式输出缓冲预算，避免 64M 像素默认上限带来的主线程卡顿和不可控峰值。

## Context

`completeComposition()` 当前在 `@MainActor` 同步创建整图 context；当前 API 最终返回单个 `CGImage`，因此分块绘制不能消除最终整图 backing store。这个 PR 只承诺后台合成、预算拒绝、取消和状态正确；文件后端/分块导出属于另一种 API。

## Implementation steps

1. 在 MainActor 捕获不可变 composition snapshot 和 generation；参照现有 preview 路径在后台调用 compose，完成后回 MainActor 发布。
2. 合成期间支持取消/代际失效；旧任务不得完成新会话、清理新窗口或回调两次。
3. `StitchConfiguration` 增加明确的 output byte budget。`validateOutput` 使用 overflow-safe 的 `bytesPerRow * height` 计算，并保留高度、帧数、像素数限制。
4. 预算只描述最终输出缓冲；测试和文档不得把它宣称为整个进程峰值。若需要更大输出，另建文件后端任务。
5. 增加边界、溢出、取消、失败保留会话和后台执行测试；用现有滚动截图回归素材检查内容连续性。

## Acceptance criteria

- [ ] 最终 compose 不在 MainActor；主线程只做快照和状态发布。
- [ ] byte budget 在 `CGContext` 分配前生效，并对乘法溢出返回 `outputLimitExceeded`。
- [ ] 合成成功、失败、取消、开始新会话四条路径不会重复回调或污染状态。
- [ ] 现有慢/快/变速/回滚、固定栏、gap fail-fast 和接缝测试不回归。
- [ ] 签名实机完成长图合成，主线程保持响应，超预算给出明确失败而非内存压力崩溃。
