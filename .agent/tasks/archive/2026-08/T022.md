# T022: R2 — 权限与扩展启用中心

## 元信息

- ID：T022
- 优先级：P0
- 状态：BACKLOG
- 推荐执行器：implementer
- 依赖：T013, T020

## Goal

在设置窗口提供统一、可操作的“权限与扩展”入口，让用户知道授权对象、用途、当前状态和下一步操作，不需要猜测系统设置位置。

## Rationale

当前 Overview 只有状态文本；实际使用的 `prototypeDiagnostics` 也只有状态。带“请求/打开系统设置”按钮的旧 `diagnostics` 没有被当前 tab 展示。Overview 还把 `isEventTapActive` 当作输入监控授权，状态语义不准确。

## Requirements

1. 新增设置侧栏“权限与扩展”页；Overview 和输入诊断提供跳转入口，不复制多套授权逻辑。
2. 每一项显示授权主体和用途：Fewer 主 App（屏幕录制、日历/提醒）、FewerShortcutHelper（辅助功能、输入监控）、Finder Extension（系统扩展启用，不称作 TCC 授权）。
3. 未授权时提供“请求授权”或“打开系统设置”；已授权时提供“重新检测”。Finder 深链不可用时打开最接近的 Extensions 页面并显示人工路径。
4. 打开页面不得自动弹出所有系统权限；只有用户点击才触发。
5. 状态刷新由窗口激活、授权操作完成和手动按钮触发；不得每秒在 MainActor 启动 `pluginkit`。
6. 输入监控状态使用 `isInputMonitoringTrusted`，Event Tap 活跃状态单独展示为运行诊断。

## Implementation guidance

- 用一个小型 permission row model 统一标题、主体、状态和按钮，不创建通用权限框架。
- 无法程序化请求的权限直接打开系统设置并解释需要勾选哪个 bundle。
- 状态为 unknown 时显示“无法确认”及重新检测，不伪装成未授权。

## Acceptance criteria

- [ ] 用户从设置首页最多两次点击可到达每一种授权/扩展入口。
- [ ] 页面准确显示主 App、Helper、Finder Extension 名称，不让用户授权错进程。
- [ ] 辅助功能、输入监控、屏幕录制、日历/提醒和 Finder Extension 均有操作入口。
- [ ] 拒绝授权、稍后授权、已授权、Helper 未运行、扩展 unknown 均有正确状态和恢复动作。
- [ ] 无自动连环权限弹窗；状态刷新不卡住设置主线程。
- [ ] UI Tests 覆盖页面导航、按钮存在和授权主体文案；实际系统设置深链签名实机验证。
