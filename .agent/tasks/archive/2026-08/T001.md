# T001: 修复输入增强“平滑滚动 + 反转方向”后鼠标滚轮失效

## 元信息

- ID：T001
- 标题：修复输入增强“平滑滚动 + 反转方向”后鼠标滚轮失效
- 优先级：P1
- 状态：DONE
- 推荐执行器：Sol

## Goal

当“输入增强 → 滚动”同时启用“平滑滚动”与“反转方向”时，鼠标滚轮在当前前台应用里不再产生任何滚动。修复后：平滑滚动 + 反转方向应正常生效（方向相反、滚动连续），且平滑滚动单独启用、反转方向单独启用、触控板直通均不回归。

## Rationale

该功能由事件监听进程（`FewerShortcutHelper`）实现：真实滚轮事件被 `ScrollEventProcessor.process` 消费，改由 `SmoothScrollEngine` 通过 `CADisplayLink` 逐帧回放合成滚动事件。经代码审查与 `CGEvent`/`NSEvent` 字段实测，定位到回放侧的高置信缺陷：

- `SmoothScrollEngine.post` 用 `CGEvent(scrollWheelEvent2Source:units:.pixel, wheelCount:2, wheel1:…)` 创建合成事件。
- 该构造器创建的滚动事件默认 `scrollWheelEventIsContinuous == 1`（实测），即被系统视为“精确/触控板”类事件。
- 当 `simulatesTrackpad == false`（默认值）时，`post` 只回放 delta，既不把 `isContinuous` 重置为 `0`，也不设置 `scrollPhase` / `momentumPhase`。
- 结果合成事件变成“`isContinuous=1` 但 `phase=none`、`momentumPhase=none`”的畸形事件。`NSEvent` 实测其 `hasPreciseScrollingDeltas == true`、`phase == .none`；接收方（`NSScrollView` 的精确手势路径）很可能将其丢弃，于是“原事件已被消费、合成替代事件又无效”导致滚轮看起来完全失效。

纯数学侧已排除问题：`ScrollEventProcessor.process`、`ScrollDecayModel`、`SmoothScrollEngine` 的符号翻转重置与衰减逻辑对正/负 delta 对称，现有 242 个 `FewerCore` 单测全部通过，JS 仿真也确认正负方向输出对称。因此“反转方向”在当前代码里并不存在独立的符号缺陷，更多是暴露了合成事件构造缺陷（负 delta 只是方向差异）。

## 现状（已确认的关键代码）

- 消费入口：`FewerShortcutHelper/EventTapController.swift` 的 `handleScroll`，返回 `true` 会吞掉原事件。
- 决策逻辑：`FewerCore/Services/InputProcessing.swift` 的 `ScrollEventProcessor.process`。
- 回放：`FewerShortcutHelper/SmoothScrollEngine.swift` 的 `enqueue` / `step` / `post`。

`post` 当前实现：

```swift
let event = CGEvent(
    scrollWheelEvent2Source: source,
    units: .pixel,
    wheelCount: 2,
    wheel1: Int32(clamping: Int(vertical.rounded())),
    wheel2: Int32(clamping: Int(horizontal.rounded())),
    wheel3: 0
)
// 仅当 simulatesTrackpad 时才设置 isContinuous / phase / momentumPhase
```

实测（`swift` 脚本）：

```text
wheel1=3  -> isContinuous=1 point=3 line=1 fixed=0.29998779296875
wheel1=-3 -> isContinuous=1 point=-3 line=-1 fixed=-0.29998779296875
```

## Implementation steps

1. 先复现，不要直接改：在 `SmoothScrollEngine.post` 临时加日志（或使用 LLDB/`os_log`），打印每次合成事件的 `isContinuous`、`scrollPhase`、`momentumPhase`、`pointDelta`、`lineDelta`；运行 `./script/build_and_run.sh run` 后，分别验证：
   - 仅“平滑滚动”（反转关）
   - “平滑滚动 + 反转方向”
   确认两种状态下合成事件字段、目标应用滚动行为，以及“反转方向”是否真的是独立触发条件。

2. 写一个先失败的回归测试，把“合成滚动事件的字段规格”抽成 `FewerCore` 内可测的纯函数（例如 `SyntheticScrollEventSpec`：输入 `simulatesTrackpad` 与 delta，输出 `isContinuous` / `scrollPhase` / `momentumPhase` / 各轴 delta 字段），并断言：
   - `simulatesTrackpad == false` 时 `isContinuous == false` 且 `phase/momentum == none`，同时保留正确的滚动 delta；
   - `simulatesTrackpad == true` 时输出合法 phase 序列（began → changed → ended + momentum）。

3. 依据复现结果修正 `SmoothScrollEngine.post`：
   - 非触控板模拟路径：构造**离散**滚动事件，正确设置 line/point delta，使接收方按预期滚动量滚动，且方向被 `reversed` 正确作用；
   - 触控板模拟路径：保持/完善 phase 与 momentum 语义；
   - 不要顺手改动 `enqueue` 的符号翻转重置、`ScrollDecayModel` 或设置 UI。

4. 若复现证明“反转方向”存在独立的符号问题（例如负 delta 在离散事件里被截断为 0），在同一修复里解决，并补对应符号回归测试。

5. 运行验证并提交，把任务置为 REVIEW（不得自行置 DONE）。
