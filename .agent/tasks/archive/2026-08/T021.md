# T021: R1 — 右键事件完整性与鼠标手势状态机

## 元信息

- ID：T021
- 优先级：P0
- 状态：DONE
- 推荐执行器：implementer（主对话先确认状态机和验收边界）
- 依赖：T013, T020

## Goal

确保普通右键在 Finder、Chrome、Safari 和系统界面可靠出现；明确手势只执行一个动作且不弹右键菜单；降低单方向短滑、抖动和折返造成的误识别。

## Rationale

当前代码从 `mouseDown` 起消费事件。4pt 点击容差与 16pt 方向段长之间形成吞点击区：轻微移动超过 4pt 但不足 16pt 时既不回放点击也不识别手势。超时或应用切换会清空 session，后续真实 `mouseUp` 可能透传；超时合成点击也可能与残余物理序列叠加。

## Requirements

1. 先写事件序列回归测试，至少覆盖 down→up、5–15pt 抖动、达到激活阈值、未匹配、匹配、超时、Escape、应用切换、tap disabled、emergency stop。
2. 把点击候选、已激活手势、完成、取消后等待物理 up 等状态显式建模；禁止只增加另一个布尔值继续叠条件。
3. 点击回放依据“是否真正激活手势”，不再依据 4pt 单点阈值；普通抖动必须得到恰好一次右键。
4. 超时/取消后必须处理剩余物理事件，不能出现合成 click 加孤立 `mouseUp`，也不能让下一次右键继承旧状态。
5. 手势激活采用总位移/有效路径和方向稳定性门槛；同方向抖动合并，明显折返需要稳定后才追加方向。规则仍为完整方向序列精确匹配，不引入模糊最近匹配。
6. recorder 与 runtime 使用同一识别器参数；保留一拖一动作和实时轨迹。

## Implementation guidance

- 最小方案是一个纯 Core 的 `MouseGestureSessionStateMachine`，事件 tap 只负责转换 CGEvent 和执行决策。
- 一段物理按键序列只有三个终态：普通点击一次；执行一个动作且无点击；手势已激活但未匹配，静默结束。
- 合成事件继续使用 marker 防止自处理；验证 marker 只忽略 Helper 逻辑，不影响目标应用接收。

## Acceptance criteria

- [ ] 0–15pt 日常抖动不会吞掉右键；每次物理点击恰好出现一个菜单。
- [ ] 匹配手势只执行一个动作，Chrome/Finder/Safari 均不弹右键菜单。
- [ ] 短滑、斜向噪声、折返、超时和应用切换不会误执行动作或留下孤立 up。
- [ ] 中键/侧键规则不回归；禁用手势时全部事件原样透传。
- [ ] recorder/runtime 方向结果一致，HUD 轨迹持续可见。
- [ ] Core 状态机测试、Helper 构建通过，并完成真实鼠标的 Chrome/Finder/Safari 录屏验收。
