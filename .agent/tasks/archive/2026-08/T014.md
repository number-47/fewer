# T014: PR2 — App Group 共享存储与保守迁移

## 元信息

- 优先级：P0
- 状态：DONE
- 推荐执行器：implementer
- 依赖：T013

## Goal

让 App、Finder Extension、Shortcut Helper 的 6 个文件 Store 统一解析到 `group.com.number47.fewer/Shared`，并以可回滚、幂等、跨进程互斥的方式复制旧数据。首个迁移版本不删除旧目录，也不在本 PR 移除 Finder `/` 例外。

## Context

`AppGroupConstants.sharedDataDirectory()` 当前固定返回 `~/Library/Application Support/Fewer/Shared`。调用方是 `SharedSettingsStore`、`InputEnhancementStore`、`CutTransactionStore`、`ModulePreferencesStore`、`ShortcutHelperStatusStore`、`TemplateStore`。原计划“复制后移入废纸篓”会破坏回滚，并与三进程并发启动冲突。

## Scope

- `FewerCore/Support/AppGroupConstants.swift`
- 6 个 Store 的默认构造路径和必要的初始化错误传播
- 新增小型、可注入路径的迁移器及单元测试
- 三个进程在首次创建 Store 前共同走同一 bootstrap

## Implementation steps

1. 把“容器 URL 解析”和“旧路径解析”做成可测试的独立输入；发布路径以 App Group Container 下 `Shared` 为唯一写入根。
2. 在返回新根前获取 App Group 内的进程间文件锁；迁移只复制已知 Store 文件和 `Templates` 目录，目标存在时绝不覆盖。
3. 使用同目录 staging + 原子 rename 发布迁移结果；迁移中断时清理 staging，保留旧数据，并记录可诊断错误。完成标记只能在逐项校验后写入。
4. 旧目录至少保留一个发布周期；不得 trash/remove。
5. `containerURL == nil` 记录明确错误。未正确签名的本地开发可以保留兼容回退，但签名发布验收必须证明三进程都解析到 container，不能把 fallback 当成功。

## Acceptance criteria

- [ ] 6 个 Store 的默认路径全部位于 App Group `Shared`。
- [ ] 测试覆盖：无旧数据、完整迁移、目标已存在不覆盖、重复执行幂等、中途失败不写完成标记、两个并发迁移者结果一致、container nil。
- [ ] 旧目录和旧文件未被删除或移入废纸篓。
- [ ] App、Helper、Extension 均在 Store 首次使用前完成 bootstrap，且共用同一实现。
- [ ] 签名运行时日志/测试证据显示三进程使用同一个 App Group 物理路径。
- [ ] 本 PR 不修改 Finder `/` entitlement，也不顺带重写 Store 的长期并发协议。
