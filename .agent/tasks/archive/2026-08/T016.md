# T016: PR4 — 可回滚 replace、文件协调与移除 `/` 例外

## 元信息

- 优先级：P0
- 状态：DONE
- 推荐执行器：implementer
- 依赖：T014, T015

## Goal

修复 `FileOperationCoordinator` 与 `TemplateFileCreator` 的 trash-then-install 数据丢失窗口，并在签名实机文件操作矩阵通过后移除 Finder Extension 的 `/` 临时全盘读写例外。

## Context

当前 `.replace` 先把目标移入废纸篓，再 move/copy 新内容；安装失败时无法原位恢复。原计划写成“复制目标后直接移动源到仍存在的目标”，该顺序本身会因目标占位失败。正确事务顺序是同目录 rename 目标为备份 → 安装新内容 → 成功删除备份；安装失败则 rename 备份回原位。

## Scope

- `FileOperationCoordinator.swift`、`TemplateFileCreator.swift`
- 一个最小内部 recoverable-replace helper（供 move/copy 两处复用）
- `FinderActionHandler` 的结果处理和 security-scoped 生命周期
- Finder entitlements、`project.yml` 及回归测试

## Implementation steps

1. 在同目录生成唯一备份名，将已存在 destination 原子 rename 到备份；不得先 trash。
2. 通过闭包执行 move/copy 安装。失败且回滚成功时保持原目标完整，并报告普通操作失败；仅回滚也失败时使用 `replacementNotRecoverable`。不新增没有调用价值的公开状态字段。
3. 用 `NSFileCoordinator` 同时协调 source（`.forMoving` 或 read）和 destination（`.forReplacing`）；accessor 内只做同步文件系统事务。
4. 成功后删除备份；失败路径不得残留半成品。用可注入失败闭包测试安装失败与回滚失败，不依赖权限竞态制造测试。
5. 在签名 Debug/本机包上先临时去掉 `/` 例外，验证 `/Users` 与 `/Volumes` 下的 create folder、cut/paste、keepBoth/skip/replace、template create、open/refresh。
6. 只有矩阵通过才从 entitlements 和 `project.yml` 正式删除例外。若失败，不恢复 `/` 作为“完成”；任务转 BLOCKED，并重新规划 main-app 执行或持久 security-scoped 授权。

## Acceptance criteria

- [ ] move replace 和 template replace 成功后新内容正确、源语义正确、无备份残留。
- [ ] 安装失败后旧目标逐字节恢复；回滚失败才返回 `replacementNotRecoverable`。
- [ ] `NSFileCoordinator` 同时覆盖源与目标，不只包裹目标 URL。
- [ ] 现有 keepBoth/skip/非法移动测试不回归；新增成功、安装失败、回滚失败、清理失败和目录替换测试。
- [ ] Finder 调用方只把 `.moved` 当成功，security-scoped access 覆盖完整异步操作期。
- [ ] 签名实机矩阵通过后，entitlements 和 `project.yml` 均不再含 `/` 临时例外；失败则明确 BLOCKED。
