# T023: R3 — Finder 菜单可见性与生命周期修复

## 元信息

- ID：T023
- 优先级：P0
- 状态：DONE
- 推荐执行器：implementer
- 依赖：T013, T020, T021, T022

## Goal

在系统原生右键恢复正常后，确保 Finder 中 Fewer 菜单在支持的容器、文件、文件夹和侧栏上下文稳定出现，并为不出现的情况提供用户可见的原因与恢复入口。

## Rationale

`FinderSync.menu(for:)` 在模块关闭、context 解析失败、services 初始化失败或 entries 为空时返回 nil；当前这些原因只有扩展日志，设置页只能显示一次 `pluginkit` 状态。用户无法区分“右键事件被 Helper 吞掉”“扩展未启用”和“扩展返回空菜单”。

## Scope

- `FewerFinderExtension/FinderSync.swift`
- `FinderMenuAdapter.swift`、`MenuBuilder.swift` 及相关测试
- Finder Extension 状态/心跳的最小诊断数据
- T022 权限与扩展页中的 Finder 状态和恢复提示
- `project.yml`/Info.plist 仅在证据证明注册范围错误时修改

## Relevant files

- `FinderSync.init/menu/makeContext`
- `FIFinderSyncController.directoryURLs`
- `ModulePreferencesStore.isEnabled`
- `ExtensionStatusService.finderExtensionStatus`
- `FewerCoreTests/MenuBuilderTests.swift`

## Requirements

1. 先在关闭鼠标手势或完成 T021 后复现，分别记录原生菜单、Fewer 菜单项和动作执行。
2. 给 `menu(for:)` 的每个 nil 分支稳定 reason code：moduleDisabled、contextUnavailable、servicesUnavailable、emptyEntries；不得记录用户文件名或完整路径。
3. 设置页显示最近一次扩展启动、最近一次 menu 请求、结果/原因和构建身份，帮助识别旧扩展或未启用状态。
4. 验证并只在必要时调整 `directoryURLs`，覆盖 Home/iCloud Drive、外接卷和侧栏；不申请比现有需求更宽的新权限。
5. 扩展启用状态刷新放后台；Finder 设置变更后验证扩展能看到同一配置。
6. 不自动杀 Finder；若系统要求重启 Finder，明确提示并由用户触发。

## Implementation guidance

- 先修第一个真实失败，不同时重写菜单 builder、动作绑定和权限模型。
- 诊断状态采用小型 Codable heartbeat，沿用共享 Store 约定；T014 完成后自然迁入 App Group。
- 动作串台由 T015 处理，本任务只保证菜单可见与原因可诊断。

## Acceptance criteria

- [ ] Finder 桌面、文件夹空白、单文件、单文件夹、多选、侧栏支持场景中 Fewer 菜单稳定出现。
- [ ] Home/iCloud Drive 与 `/Volumes` 下支持范围符合设计；不支持场景有明确说明。
- [ ] 扩展未启用、模块关闭、旧构建、context/services 失败均能在设置页区分。
- [ ] 普通系统右键菜单不受影响；关闭 Finder 模块只隐藏 Fewer 项。
- [ ] Finder 重启、App/Helper 重启和设置切换后状态一致。
- [ ] MenuBuilder 单测、完整构建通过，并完成签名 Finder 实机录屏。
