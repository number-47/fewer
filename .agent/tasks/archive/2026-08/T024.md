# T024: R4 — 菜单栏日历滚动性能

## 元信息

- ID：T024
- 优先级：P1
- 状态：DONE
- 推荐执行器：implementer
- 依赖：T013, T020

## Goal

让菜单栏日历使用鼠标滚轮和触控板连续逐行滚动时保持跟手，不因整棵 SwiftUI 树重算或 EventKit 查询而卡顿；继续遵守“一行一行滚动”。

## Rationale

`CalendarScrollCoordinator` 在每个 scroll event 发布 `offsetY`，触发包含 42 个日期格和 agenda 的视图更新；每次 `scrollAnchor` 改变又在 MainActor 同步调用 `eventStore.events(matching:)`，并取消、重启 reminder fetch。快速滚动时这些工作互相放大。

## Scope

- `FewerApp/Views/MenuBarCalendarView.swift`
- `FewerApp/Services/SystemCalendarService.swift`
- 日历/事件相关 Core tests，必要的 UI 性能标记

## Relevant files

- `CalendarScrollCoordinator.start`
- `MenuBarCalendarView.scrollByRows/loadSystemEvents`
- `SystemCalendarService.loadEvents/events(on:)`
- `CalendarMonth` 和现有日历测试

## Requirements

1. 在修改前记录连续滚动的主线程 profile、body 更新次数、EventKit 查询次数和 reminder 取消次数。
2. 高频像素偏移隔离到轻量 AppKit/layer 路径或显示刷新节奏，不让整棵 SwiftUI 日历在每个 wheel event 重建。
3. 每次可见行推进最多一步；大 delta 保留剩余量后续消费，不得一次跳多周/月。
4. EventKit 查询移到专用串行后台边界，先映射为 Sendable 值再回 MainActor 发布。
5. 滚动期间合并可见范围请求，手势停顿/结束后加载最终范围；最近范围使用有界缓存，事件库变更时失效。
6. generation/cancellation 防止旧月份结果覆盖新月份；权限和语言变化仍能刷新。

## Implementation guidance

- 不引入第二套日历；保留 `MenuBarCalendarView` 单一实现。
- 优先隔离高频 transform 和数据加载，避免仅通过增加动画时长掩盖卡顿。
- EventKit 是否允许跨线程必须按专用队列拥有 `EKEventStore` 的方式实现和验证。

## Acceptance criteria

- [ ] 鼠标滚轮和触控板均逐行移动，一个事件不跨多行。
- [ ] 连续滚动时主线程无同步 EventKit 查询，reminder fetch 不按每行反复取消重启。
- [ ] 高频 offset 不导致 agenda/权限区域逐事件重算。
- [ ] 停止滚动后最终月份、选中日期、事件和提醒正确，无旧结果闪回。
- [ ] Time Profiler/符号日志显示主线程无明显滚动长任务；签名 popover 连续滚动录屏无肉眼卡顿。
- [ ] 时区、语言、跨月、今天、权限变化和事件库变更测试通过。
