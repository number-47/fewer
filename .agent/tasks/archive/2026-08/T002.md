# T002: 五模块模型、偏好与 schema 4 迁移

## 元信息

- 优先级：P0
- 状态：DONE
- 推荐执行器：implementer

## Goal

将聚合 `dashboard` 迁移为 `cpu`、`gpu`、`memory`、`disk`、`network` 五个独立模块，并为后续状态项组件提供稳定、可迁移的偏好模型。

## 范围

- `FewerCore/Models/ModuleModels.swift`
- `FewerCore/Models/StatusBarMetricsOptions.swift`
- `FewerCore/Services/ModulePreferencesStore.swift`
- `FewerApp/Services/ModuleHost.swift`
- `FewerCoreTests/ModuleModelsTests.swift`

## 要求

- schema 升级为 4；新增 `SystemMonitorModuleID`、`MonitorWidgetKind`、`MonitorModulePreferences`，保存刷新间隔、组件及顺序、颜色和模块专属选择。
- 删除 dashboard 描述符及其命令；CPU 不得注册命令。
- 新安装默认启用全部模块；状态栏默认 CPU、内存、磁盘、网络、日历，GPU 不显示。
- v3 迁移时以 dashboard 是否在菜单栏显示为总开关，按旧 metrics 映射 CPU/内存/磁盘/网络，GPU 只启用不显示；保留日历、其他模块、显隐与排序，dashboard 位置展开为五个模块。
- 旧 metrics 只作为兼容解码/迁移输入，不能作为新运行时设置入口。
- 回归测试覆盖迁移、排序、未知 ID 清理与 GPU 默认隐藏。

## 排除项

- 不修改 `.agent` 协调文件，不回退用户已有改动。
