# T052: AI 截图翻译的兼容服务与签名运行时验收

## Metadata
- Priority: P1
- Status: BLOCKED
- Dependencies: T051

## Goal
以本机 OpenAI-compatible 桩服务验证签名 Debug 的 AI 翻译真实请求边界，并与现有截图翻译运行时证据分层记录。

## Scope
- 仅增加必要的测试夹具/验证脚本与任务证据；不改变产品能力。
- 覆盖保存并测试、成功译文、鉴权失败、限流、超时、无效 JSON、取消和目标语言重译。

## Acceptance Criteria
- 签名 Debug 通过本机兼容服务完成系统默认、手动切 AI、显示译文和目标语言切换；服务仅收到文本和语言参数。
- 物理全局按键、屏幕录制、Apple Translation、多显示器与真实外部供应商证据独立记录，未完成不得误报。

## Validation
- xcodegen generate、./script/verify.sh、./script/build_and_run.sh --verify、git diff --check，以及人工签名 Debug 矩阵。

## Evidence
2026-09-03：新增 `script/verify_ai_translation_stub.py` 与 4 项 Python 单测。桩服务仅监听 `127.0.0.1`，输出完整 Chat Completions endpoint；支持 success、401、429、500、invalid-json、timeout 和 `--once`，请求日志仅含 method/path/model 与语言字段/image/coordinates 存在性，绝不输出 OCR 文本、请求正文或 Authorization。

2026-09-03：`PYTHONDONTWRITEBYTECODE=1 python3 script/test_verify_ai_translation_stub.py` 通过（4 tests）；`python3 -m py_compile` 通过；`xcodegen generate`、`./script/verify.sh` 通过（FewerCore 400 tests、完整 Debug build）；`./script/build_and_run.sh --verify` 通过并重签 Debug 主包及嵌套组件；`git diff --check` 通过。

2026-09-03：用户提供的 `http://127.0.0.1:8000/v1/chat/completions` 可访问，`/v1/models` 列出 `translategemma-12b-it-6bit`。直接 POST 证明该模型的本地 `chat_template.jinja` 需要一个 TranslateGemma 专用 user content 数组（`type`、`source_lang_code`、`target_lang_code`、`text`）；但当前 oMLX 文本模型 API 预处理会将 OpenAI content parts 扁平化为字符串，模板因而返回 HTTP 400。此为 oMLX 模型适配缺口，不能仅靠 Fewer 的通用 Chat Completions 文本请求修复。

阻塞证据：本轮未以用户身份授予 Automation/辅助功能/屏幕录制权限，未执行物理全局快捷键、选区/OCR、浮窗系统→AI 切换、目标语言重译、Apple Translation 语言资源、Retina/多显示器矩阵或真实外部供应商调用。构建、桩服务和签名校验均不能替代这些证据。

解除条件：先为 oMLX 的 TranslateGemma 请求保留专用 content 数组（服务端 message extractor/适配器），或改用接受标准字符串 Chat Completions 的本地模型；随后用户在签名 Debug 运行中自行授予必要权限，使用有效本机 endpoint 完成物理截图翻译矩阵。真实外部供应商仅在用户提供其 endpoint、模型与密钥后另行记录。
