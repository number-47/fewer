# T031: ModulePreferences 损坏恢复

## 元信息

- 优先级：P1
- 状态：DONE
- 推荐执行器：implementer
- 依赖：T030

## Goal

防止损坏 module preferences 静默重新启用所有模块并覆盖用户选择。

## Requirements

- 区分 missing、valid、corrupt；missing 保持首次安装默认，valid 正常 reconcile。
- corrupt payload 原子移为唯一 `module-preferences.corrupt-<timestamp>.json`；内存恢复为全部模块禁用，并向设置 UI 提示。
- 在用户明确恢复默认或首次编辑前不得写回；corrupt 时 `isEnabled` 返回 false。

## Validation

- 覆盖缺失、有效迁移、损坏备份、重复损坏唯一命名、无自动覆写与禁用命令路径。

## Completion Report

- corrupt payload 会备份为 `Recovery/module-preferences.corrupt-<timestamp>.json`，重名时追加后缀且不覆盖原备份。
- 恢复标记使重启后的 load/isEnabled 持续 fail-closed；首次编辑或“恢复默认”后才清除标记并持久化。
- 设置页显示恢复提示及恢复默认入口。
- 通过 ModuleModelsTests 15/15、完整 `./script/verify.sh`：360 Core tests/0 failures、Debug build、模板、产物和 diff 检查均通过。
