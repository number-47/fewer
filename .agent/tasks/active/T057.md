# T057: 普通截图保留 OCR 翻译浮窗

## Metadata

- Priority: P1
- Status: BLOCKED
- Dependencies: T046

## Goal

普通截图可截入当前 OCR 翻译浮窗，同时保持重新发起截图翻译时替换旧结果的既有行为。

## Scope

- 修改普通截图启动、结束和取消期间的 OCR 浮窗保留行为。
- 仅在普通截图的有效会话内暂时抑制 OCR 窗口失焦关闭，并置于截图遮罩之上且不拦截选区操作；结束、取消或失败后恢复默认规则。
- 不改变 OCR 识别、翻译请求、截图图片数据、固定按钮或持久化行为。

## Acceptance Criteria

- 有 OCR 结果窗时，启动普通区域、窗口、智能或全屏截图不会关闭该窗，且输出图片包含该窗。
- 截图遮罩显示时 OCR 窗仍可见，且鼠标事件由遮罩接收。
- 普通截图结束、取消或失败后，未固定 OCR 窗口恢复原有下一次失焦关闭行为。
- 新截图翻译仍立即关闭并替换旧 OCR 结果，不保留多份文本。
- `git diff --check` 与 Fewer Debug 构建通过；实机截图矩阵通过后方可归档。

## Validation

- Fewer Debug 无签名构建。
- `python3 script/verify_agent_state.py`
- `git diff --check`
- macOS 26 签名运行：分别用区域、窗口、智能、全屏普通截图截取未固定和固定 OCR 窗；验证完成、取消、失败后失焦关闭，以及连续 OCR 替换。

## Evidence

- 2026-09-04：用户实机报告普通截图无法截取 OCR 浮窗。静态路径显示 `ScreenshotService.begin(_:)` 在每次截图启动时无条件调用 `ocrCoordinator.cancel()`；该调用会关闭结果窗。即使移除该调用，截图遮罩窗口成为 key window 仍会触发未固定 OCR 面板的失焦关闭，必须将两处一起处理。
- 2026-09-04：普通截图会话现在只临时抑制 OCR 面板的失焦关闭，不再取消 OCR 协调器；完成、取消、失败和滚动截图取消均恢复默认失焦关闭规则但不关闭当前 OCR 窗。重新触发截图翻译仍清除该临时状态并调用既有取消/替换路径。Fewer Debug 构建、FewerCore 413 项测试、状态校验和 `git diff --check` 通过；`./script/build_and_run.sh --verify` 成功重建、签名并启动最新 Debug 包。
- 2026-09-04：用户反馈截图遮罩出现时 OCR 窗仍不可见。原因是遮罩处于 `.screenSaver` 层而 OCR 窗仅为 `.floating`。普通截图期间 OCR 窗现在提升至 `.screenSaver + 1`，并设置 `ignoresMouseEvents = true`，所以可见但不会拦截选区操作；恢复时回到 `.floating` 和可交互状态。Fewer Debug 构建、FewerCore 413 项测试、状态校验和 `git diff --check` 通过；`./script/build_and_run.sh --verify` 成功重建、签名并启动最新 Debug 包。

解除条件：在已授权屏幕录制的 macOS 26 签名 Debug 运行中，对未固定与固定 OCR 窗分别执行普通区域、窗口、智能和全屏截图，确认成图均包含 OCR 弹框；再验证完成、取消、失败后的下一次失焦关闭，以及连续 OCR 替换。通过后由主对话归档。
