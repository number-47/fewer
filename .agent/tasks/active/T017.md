# T017: PR5 — 经签名验证的双向 XPC 命令通道

## 元信息

- 优先级：P0
- 状态：BACKLOG
- 推荐执行器：implementer（主对话先确定安全边界并最终验收）
- 依赖：T028

## Goal

把 Helper→App 的模块命令和 App→Helper 的运行时控制从无身份验证的 DistributedNotificationCenter 迁到可校验双方身份的双向 XPC 连接；数据变更广播继续使用 DNC。

## Context

`ModuleCommandXPCServer.swift` 名称虽含 XPC，实际只是 DNC observer。现有 Helper 通过 `SMAppService.loginItem(identifier:)` 注册，Helper `Info.plist` 没有 Mach service 声明，因此原计划“主 App 直接托管命名 listener”不是已成立的部署事实。

## Mandatory architecture gate

在替换生产通道前，先用最小签名探针证明：

1. Login Item 能通过明确的 launchd/MachServices 配置拥有命名 listener；
2. 主 App 能建立并重连该连接，Helper 能经同一已认证连接回调 App；
3. listener 能从 audit token 校验 team ID、bundle ID/designated requirement 和必要 entitlement；
4. 非 Fewer 测试客户端被拒绝。

探针失败时停止并将任务标记 BLOCKED，重新规划部署拓扑；不得静默保留 DNC 特权命令。

## Prerequisite

T028 必须先提供当前部署拓扑或 `SMAppService.agent` 替代拓扑的签名 probe 证据；未通过前不得修改生产特权命令通道。

## Implementation steps

1. 将 Helper 作为 launchd 管理的连接端，主 App 建立长连接并导出回调对象；复用该连接承载 App→Helper 控制和 Helper→App 模块命令。
2. 协议只接受强类型、有限集合的命令和 reply；边界再次校验模块/命令允许列表，不接受任意 selector、路径或脚本。
3. listener 验证 App 身份；App 侧验证连接到预期 Helper 服务的签名/服务身份。中断和失效时指数退避重连，不在队列中无限积压输入动作。
4. 删除 `moduleCommandNotification` 和 `inputEnhancementControlNotification` 的命令收发；设置变更、状态变更等广播保留 DNC。
5. 添加协议、身份判定、拒绝路径、重连和一次投递测试；签名实机完成正向/伪客户端验证。

## Acceptance criteria

- [ ] Mandatory architecture gate 四项都有可复现证据。
- [ ] 未通过签名要求的本地进程不能触发截图、系统控制或输入切换命令。
- [ ] 两个特权 DNC 通道已移除，普通状态广播保持原行为。
- [ ] 连接中断不会崩溃、死锁、无限排队或重复执行命令。
- [ ] 无签名构建和核心单测通过；签名 App+Helper 完成双向往返和拒绝测试。
