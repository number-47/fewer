# T028: 签名 XPC 架构探针

## 元信息

- 优先级：P0
- 状态：BLOCKED
- 推荐执行器：implementer
- 依赖：T027

## Goal

在签名 GUI 实机上确定 Helper 的真实 Mach service 部署拓扑，并记录双向、身份校验、重连及伪客户端拒绝证据。

## Requirements

- 优先验证现有 `SMAppService.loginItem`；若不能拥有 launchd Mach service，则改用 `SMAppService.agent` 并验证 Event Tap、HUD、WindowServer 行为。
- listener 在接受连接前通过 audit token 校验 Team ID、bundle ID、designated requirement 与 App Group entitlement。
- App 与 Helper 必须在同一连接上完成双向 ping/reply、断线后有限退避重连；非 Fewer 客户端必须被拒绝。
- 两种拓扑都不能通过时标记 BLOCKED，禁止实施 DNC 伪替代。

## Validation

- 保存签名、launchd、正向/反向往返、重连和伪客户端拒绝日志。
- 验证 Helper 输入与 HUD 行为未退化。

## Blocker Evidence

- 2026-08-25 签名 Debug Fewer、Finder Extension、Shortcut Helper 的 Team ID 均为 `6P34MCYUCS`，App Group 均为 `6P34MCYUCS.group.com.number47.fewer`。
- `launchctl print gui/501/com.number47.fewer.shortcut-helper` 显示 Login Item endpoint 已登记，但 job 为 `spawn failed`，最后退出码为 `78 (EX_CONFIG)`；当前 Helper 源码没有 `NSXPCListener`。
- 因此当前 Login Item 不能作为已验证的双向 XPC 服务；改为 `SMAppService.agent` 前需要独立的 signed GUI/Event Tap/HUD probe，不能移除生产 DNC。

## Current Investigation

- 2026-08-25 复核 `launchctl print`：Login Item 已登记同名 endpoint，但没有源代码调用 `NSXPCListener.service()`；直接启动签名 Helper 可以保持运行，故先实现不承载生产命令的最小双向 ping probe，验证当前 Login Item endpoint 是否可用。
- 最小 probe 经过 `xcodegen generate` 与定向编译后撤回：当前 macOS 26.5 SDK 的公开 `NSXPCConnection` 只有 audit session identifier、PID 与 effective UID/GID，不提供 `auditToken`；`SecCodeCopyGuestWithAttributes(... kSecGuestAttributeAudit ...)` 所需的 audit token 无法从该 API 获得。用 PID 获取 `SecCode` 不满足本任务的 audit-token 验收，未采用。
- 需要用户决定：允许采用低层 `xpc_connection_t` listener 以保留 audit token，或明确调整安全验收。两者都是架构边界改变；在决定前不得修改生产 DNC 通道。
